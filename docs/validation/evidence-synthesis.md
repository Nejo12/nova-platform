## Feature-request filter

Before promoting any request into M2 requirements, ask:

1. Is the underlying problem repeated across multiple participants?
2. Is the problem severe or economically meaningful?
3. Does solving it strengthen Tessnova's core job?
4. Can it be solved without turning Tessnova into a generic business suite?
5. Is the requested feature actually a workaround for a different underlying problem?
